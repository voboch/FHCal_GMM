# Figures, numbers and tables

Редакция 2026-11-12. Профиль представления для §25. Научные основания
проверяются по §10; проектные термины — по актуальным источникам и §00.
Прежние истории ошибок сохранены в снимке исходных конвенций. Их числа
не являются актуальными результатами для новой работы.

## F1. Число имеет однозначный смысл

Числа результата берутся из канонического источника. Читателю доступны:
величина, единицы, популяция/выборка и её размер, окно отбора, reference,
статус train/validation/test/in-sample и смысл неопределённости. Общие условия
можно указать один раз в видимой подписи блока; исключения пометить локально.
Контекст указывается по применимости: reference — для сравнения; split и
происхождение подгонки — для результатов, зависящих от обучаемых или подбираемых
величин. Неприменимые поля не заполнять искусственно.
Для процентов назвать базу; для σ — сравниваемую величину и метод оценки.
Точность записи соответствует оценённой неопределённости. Одно измерение или
single seed явно помечаются; отсутствие оценки ошибки не означает нулевую ошибку.

Не смешивать MC truth, reconstruction и hybrid observable; у hybrid назвать
все компоненты. Для генерации различать reference, prior и model, включая
величины, перенесённые из входа без предсказания. Использовать действительную
систему, энергию, species, selection и версию данных; сверять их с источником,
а не переносить исторический пример из инструкции.

## F2. Сравнение отвечает заданному вопросу

Назвать reference и убедиться, что он присутствует. Сопоставимость популяций,
окон, preprocessing, fitted quantities и estimator проверяется по §10. При
несопоставимости группировать результаты и ограничивать интерпретацию.
Несколько одновременных изменений не устанавливают причину эффекта.

При общих событиях/файлах/seed учитывать зависимость и оценивать неопределённость
самого контраста. Различать training-seed variation, evaluation variation,
SD, SE, bootstrap CI и systematic uncertainty. Выбор статистического теста,
единицы независимости и числа повторов относится к протоколу конкретного
эксперимента: две прежние схемы HIC не объявляются исчерпывающими для всех задач.
Для соответствующих дизайнов HIC они сохраняются в
[профиле сравнений](profiles/hic-comparisons.md); на HGND автоматически не
переносятся. Уже принятый тест при переносе результата в доклад не менять. Для нового
анализа следовать §10 и проектному протоколу.

Систематический сдвиг, сценарий коррекции и независимо проверенная коррекция
обозначаются отдельно. Перенос на другую область требует указать направление,
изменённые условия и независимую проверку. Подгонка по оцениваемому исходу
не доказывает closure; улучшение вспомогательной метрики не доказывает физическую
пригодность. Отсутствующие данные/калибровки/response/требования обозначать
как пробелы, не придумывать feasibility budget.

## F3. Таблица читается без расшифровки

Заголовки именуют величину и единицу. Обозначение «лучше» добавляется только
к метрике с определённым желательным направлением; физическим значениям,
перечням и административным таблицам искусственное направление не назначается.
Условия F1/F2 задаются столбцами или одной видимой подписью. Крупную таблицу
сократить до сравнения, необходимого для тезиса; полную оставить в приложении.

Для результата, зависящего от подгонки, указать происхождение fitted quantities.
Для HIC указать сплит, состав и размер выборки подгонки prior и привязку
нормализации к checkpoint, где они влияют на результат. Для HGND указать
выборку, поколение данных, физическую настройку и роли данных для обучения,
калибровки, выбора порога и оценки. Для чистого референса явно указать
отсутствие подгонки, если это существенно для сравнения.
HTML-комментарий или метаданные служат машинной проверке и не заменяют видимую
информацию. Жирный шрифт имеет одно объяснённое значение. Отозванные значения
сохраняются в реестре и истории версий; актуальная таблица не обязана содержать
все прежние зачёркнутые строки.

Таблица-источник для статьи или диссертации проходит проверку F1–F3 до переноса.
Для Markdown используйте `HIC-NeuralFusion/scripts/lint_table_headers.py`
как предварительную проверку. Редактор проверяет видимый контекст и применимость
каждого замечания. Ложное срабатывание кратко объяснить в существующем ревью.

## F4. График показывает доказательство

Каждая панель отвечает на часть тезиса. Добавлять ratio/residual, если без него
нельзя оценить заявленное расхождение; не дублировать уже показанный контраст.
Нейтральная линия и центр расходящейся шкалы соответствуют определению:
**1 для A/B; 0 для A−B или A/B−1**. Для отношения указывать знаменатель;
при нулевом знаменателе не создавать конечное значение. Диапазон должен
показывать сравнение; отклонение от симметрии обосновывается смыслом величины.

Референс, данные и модель различаются не только цветом: использовать тип
линии/маркера и явную легенду. Binned quantities показывать ступенями или
точками с определённым смыслом; сглаживание не должно изобретать структуру.
Конкретная семантика маркеров едина в серии. Если показываются точки MC,
пометить simulation, не полагаться только на форму маркера.

Статистические и систематические ошибки различать в графике и подписи.
Тип и метод неопределённости указывать; resampling — с числом повторов и
единицей resampling по §10. Схема алгоритма не требует выдуманных error bars.

## F5. Видимая подпись и точный источник

У результатного рисунка подпись и ближайший видимый контекст вместе сообщают,
что показано, условия сравнения, поддержанный вывод и существенное ограничение.
Не дублировать вывод, уже ясно выраженный в заголовке слайда. Подпись к схеме
или определению объясняет содержание и роль без придуманного эксперимента.
Самостоятельная фигура сохраняет нужный контекст в собственной подписи. Краткая
ссылка ведёт к точному источнику: артефакт/таблица/строка и версия либо хеш
при доступности. Полные пути, run IDs, script и commit находятся в notes,
реестре источников или воспроизводимом приложении, а не обязательной длинной
строкой на каждом слайде.

На самостоятельно распространяемом рисунке оставить короткие species,
truth/reconstruction, system/energy и selection labels. На слайде общие
условия можно вынести в читаемую подпись. Любой panel, ограничивающий основной
вывод, должен быть назван. Читательские названия одинаковы в тексте и изображении.

## F6. Профиль статьи и диссертации

Готовить рисунок под фактический конечный размер. Для текущего HEP-профиля:
обычно 8 pt основной шрифт, минимум 7 pt после вставки, закрытая рамка,
тики внутрь на четырёх сторонах, без декоративной сетки. Требования площадки
проверяются отдельно; точный размер зависит от шаблона. Предпочитать векторный
экспорт с внедрёнными шрифтами. Масштабирование допустимо, если конечные
надписи читаемы; сам по себе параметр width не является ошибкой.

## F7. Профиль презентации

Проверять графики в конечном слайде. Рабочие начальные размеры: 24–28 pt
основного текста, 18–20 pt значимых подписей/осей; это ориентиры для обычного
формата 16:9, не автоматический пропуск проверки. Если не помещается,
сократить или разделить. Отдельный handout не отменяет читаемость проекции.

Легенда не перекрывает ни данные, ни ошибки, ни reference lines, ни подписи.
Для одинаковых серий использовать общую внешнюю легенду. Изменение геометрии
требует нового рендера. Не вставлять статью целиком как мелкое изображение.

## F8. Общее оформление и проверка

Использовать общий style helper, когда он доступен. Для исходного набора HIC/HGND:
reference — near-black, prior — firebrick, model — blue; различие дополнено
типами линий/маркеров. Ordered parameter — последовательная шкала,
unordered categories — категориальная; viridis допустим, jet не использовать.
Проверить контраст и различимость без опоры только на цвет. В тёмной теме
адаптировать яркость, сохранив роли.

Units, normalization, scale и окна указаны. Логарифмическая шкала выбирается
по задаче; скрытое отсечение недопустимо. Автоматические либо общие для
сравниваемых панелей фиксированные пределы допустимы после проверки всех
точек и концов error bars; намеренный crop явно помечается. Для HIC central
сопоставлять с peripheral, если вывод касается обоих; pooled result не
приписывать одному specialist. При парном расположении central — слева/сверху.

Проверить текст/формулы/легенды, корректность SVG/XML при соответствующем
формате, выход за границы и конечный рендер, включая используемый Backup.
Линтер проверяет форму; редактор проверяет, что подпись и вывод действительно
соответствуют показанным данным. Приёмка — по R8 и §25.3, без второго
пересказа правил, способного разойтись с F1–F8.
